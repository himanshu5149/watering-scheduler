# Plant Watering Schedule Generator

A free, no-login, no-backend web tool. Pick a plant, a pot size and your light, and get a **baseline watering interval**, the **date of the next check**, and a **printable black-on-white card** you can tape to the pot.

It is a **calculator, not a care coach**. The interval and date it outputs are a suggested **soil-check schedule**, not an instruction to water on a fixed date. Every result carries a plant-appropriate moisture-check method in large type, plus the same rule: conditions and plant needs vary — check the growing medium each time, and water only when it is appropriate for that plant.

## Run it

```bash
npm install
npm run dev      # local development
npm run build    # static production build in dist/
```

The production build is fully static — no server, no API, no cookies, no analytics. Everything runs client-side, so the page keeps working offline once saved.

## How the calculation works

Implemented exactly in `src/lib/schedule.ts` (`calculateSchedule`):

```
interval = baseDays
interval ×= potFactor      // Small: 0.8 · Medium: 1.0 · Large: 1.3
interval ×= lightFactor    // Low: 1.4 · Bright indirect: 1.0 · Direct: 0.8
interval ×= seasonFactor   // Growing: 1.0 · Dormant: 1.3
interval = Math.max(1, Math.round(interval))
```

- `nextCheck = (lastWatered ?? today) + interval days` (local time), formatted as e.g. `Fri, 27 Nov 2026`. The last-watered date is an optional input; when it is left blank, the card explicitly labels the assumption (*“last watered unknown — today assumed”*).
- If the suggested check date has already arrived or passed, the card says a **soil check is due** (and how long it has been) — it never tells the user to water automatically. A one-tap *"Checked and watered today? Restart the schedule from today"* button then recalculates after a missed watering, keeping every other input.
- Sanity clamp: if the final interval is under 2 days, the result shows a soft note — *"This plant drinks fast — check soil daily rather than following a fixed number."*
- Optional convenience: a pot diameter in cm maps to a bucket (`potSizeFromCm`): ≤12 cm → Small, 13–20 cm → Medium, >20 cm → Large.

To retune the tool, edit the three factor tables at the top of `src/lib/schedule.ts` (`POT_FACTORS`, `LIGHT_FACTORS`, `SEASON_FACTORS`). A factor above 1 stretches the interval; below 1 shortens it.

### The soil-check framing

The output is a check cadence, not a watering order:

- Each card shows a plant-appropriate moisture-check method, set per plant with the optional `check` field in `src/lib/plants.ts` (`CHECK_GUIDANCE` in `src/lib/schedule.ts` holds the copy): `standard` (finger 2–3 cm), `succulent` (let the pot dry out fully — go by weight or a skewer), `moisture-loving` (water when the top 2–3 cm just starts to dry), `orchid` (judge by the roots in bark, not the surface). These are coarse buckets on purpose — no per-species guarantees.
- Cards state what to do when the medium is still moist: wait and check again in a day or two.
- Every card includes a concise drainage warning: let excess drain away and never leave the pot standing in water.

## Where the plant table lives

`src/lib/plants.ts` — a plain array of objects:

```ts
export const PLANTS: Plant[] = [
  { name: 'Snake Plant', baseDays: 21 },
  { name: 'ZZ Plant', baseDays: 18 },
  // …30 entries
];
```

`baseDays` is the interval for a **medium pot, bright indirect light, growing season** — everything else is a factor on top.

### How to add a plant

Append one line to `PLANTS` in `src/lib/plants.ts`:

```ts
{ name: 'Hoya', baseDays: 14 },
```

Nothing else changes — the searchable chip list, the result card and the calculation all read from that array.

Users can also add a one-off plant directly in the app: **"My plant isn't listed — enter it myself"** opens a small form for a name and a base interval in days (1–365). It is flagged `custom: true` and flows through exactly the same calculation as a list plant.

## Print behaviour

The `@media print` block in `src/index.css` hides all inputs, buttons, navigation and page sections, and outputs a black-on-white card: plant name, the check interval in very large type, the next check date (or “a soil check is due now”), the input summary line — including the labelled last-watered assumption — a plant-appropriate moisture-check method, the “still moist → wait” rule, the disclaimer with the drainage warning, and the footer line *"Generated by Plant Watering Schedule Generator — a free calculator, not a care app."* Layout targets A5/A6 so the card can be taped to a pot. Backgrounds and images are suppressed to save ink.

## Accessibility

- Real `<label>` / `<fieldset>` / `<legend>` associations everywhere; chips are real buttons with `aria-pressed`.
- The result region is wrapped in a persistent `aria-live="polite"` container so screen readers announce the schedule when it appears.
- All tap targets are ≥44 px; system font stack; high-contrast palette.

## Known limitations

This tool does not sense real soil moisture, does not send reminders, and does not account for humidity, temperature, soil type, pot material, drafts, or the size and health of the plant. Its output is a starting point only — a baseline interval to check against, not an instruction to water on autopilot. If the schedule and the soil disagree, believe the soil.

## Roadmap (in order, deliberately small)

1. ✅ Static schedule generator with printable card (this build).
2. ✅ “Recalculate from my actual last watering date” input — the card counts from the real date and plainly labels it when it has to assume today.
3. Optional multi-plant list that prints as a single page.

No accounts and no notifications, on purpose — that is where the cost and the false confidence creep in.
